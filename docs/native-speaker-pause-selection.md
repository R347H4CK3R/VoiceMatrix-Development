# Native speaker-to-reference pause integration

LocalSpeakerPolicy now pairs two adjacent exclusive spans carrying the same diarizer-assigned speaker label when each contains at least 1.5 seconds, the gap is at most 600 ms, and the combined span is at most 12 seconds. Any other speaker segment intersecting that gap blocks the pair, including overlap removed by the sweep. Pairing is disjoint, never transitive; existing 150 ms trimming, three-candidate bound and 3–8 second primary reference selection remain. This relies on the native model's labels and does not import ECAPA embeddings into iOS.

LocalSpeakerDiarization selectionPolicyVersion is now 3. Retained v1/v2 analyses are first validated against their exact old window rules with pause pairing disabled; only valid raw segments are recomputed under v3. Unknown versions remain rejected. This is an actual integration in the on-device candidate path, not an assertion that the CoreML models ran successfully.

Representative integration evidence: the actual Swift selector consumed the preserved CPU model-derived intervals for the real LibriSpeech A-B-A fixture. It kept two groups and selected six crops. Independent source-boundary checks mapped all crops to the correct A/B source, and FFmpeg decoded each crop to the requested duration within 1 ms. Results are in qa/cloud-speaker-real/native-selection-proof.json. These are regression samples, not a fresh natural-conversation benchmark. Native policy tests also cover paused short turns, unchanged legacy behavior, blocking a different-speaker interjection, and blocking removed overlap. Twenty-two native-policy/source-contract tests passed; Apple model execution remains unrun.
