# Reference-profile integration review

Review found and fixed an engine-compatibility defect in the initial direct-recording flow: it admitted transcripts up to 2,000 characters, while the actual F5 planner accepts at most 512 UTF-8 bytes. A regression case first failed by saving an incompatible 513-byte transcript.

F5SpeechChunks now exposes one reference validator and byte-limit constant. Direct profile creation, the form's save gate and actual F5 generation planning use that contract. Tests cover 512-byte English and 510-byte multibyte boundaries, and reject 513-byte English and 540-byte multibyte text. Exact reference words are retained; only surrounding whitespace is trimmed during initial creation. No transcript is truncated to fit.

The autonomous video workflow now applies the same check after saving transcription evidence but before loading F5 or consuming a preview attempt. An incompatible candidate is logged and skipped so another bounded candidate can be tried. No quality, transcript-check or speaker-identity gate was weakened.

## End-to-end coverage available here

Both portable profile tests passed, and the existing F5 whole-word/job-budget harness passed. The actual CharacterFolderStore was exercised with creation, loading, reference retrieval, duplicate rejection, audio tampering, cancellation and earlier-voice preservation. A new test changes only the transcript for an existing ID and verifies that import rejects it without changing the library index. Saved metadata then drives the actual F5 planner.

## Actual engine selection and limits

Source inspection confirms CharacterLibrary.speak passes the selected profile's referenceText and the library-verified reference URL to F5ReferenceEngine.speak. It calls the bundled F5 engine and does not fall back to an RVC evaluation voice. CharacterLibrary.convertRecording uses that reference URL with CharacterVoiceConversion, which extracts the target embedding through OfflineVoiceConverter and the bundled OpenVoice model. Saving a profile does not train either engine or RVC.

This review verified packaging, storage, transcript association and real engine planning—not neural inference. F5's Apple/MLX runtime, OpenVoice CoreML prediction, microphone/file-picker/navigation behavior and AVFoundation extraction on iPhone remain unrun. New Swift files and changed iOS paths passed frontend syntax parsing, not Apple SDK typechecking. Phone cancellation and audio resemblance still need device/listening checks.

Existing voices, model assets, licenses and prior evidence are preserved. No preview, IPA, model pack or source-feed update was published.
