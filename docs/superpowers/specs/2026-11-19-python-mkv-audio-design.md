# Python-coordinated Matroska audio, design and verification plan

Draft, no product code change. Baseline 2daf7bc plus current feature branch. First deliverable: advance a user-authorized, retained, compatible video from embedded Python request to genuine MKV to analysis PCM read from that MKV on iPhone.

## Alternatives and scope

Recommend embedded Python owning the stage flow and preparation request, with Swift performing the existing container remux and Apple AAC decode. Avoid general FFmpeg dependency or Python reimplementation of media codecs. This is Python-orchestrated conversion, not Python serialization. If literal Python Matroska serialization is a hard requirement, consider separate Python muxer over bounded native MP4 packet metadata only after establishing parity; do not duplicate the muxer upfront. An MP4 companion with equivalent content is useful for preview/OCR, but not acceptable as the analysis source.

## Contract

- Existing authorized URL normalization, Python resolver, native HTTPS transfer, acquisition receipts and supported H.264/AAC input remain. First slice accepts only files already supported by MP4SampleTable/LocalMKVExport (single AAC-LC and single H.264 track, <=720p); unsupported codecs or timelines get an explicit failure, not a hidden companion analysis. Existing legacy flows remain available explicitly.
- A new bundled Python entry point receives versioned JSON containing opaque job identity, policy version and current native-verified stage evidence, not filesystem paths or URLs handed off as capabilities. It chooses the next operation from prepare-MKV / decode-MKV / complete; Swift performs only that enumerated action in an owned job context, validates state and hands a sanitized receipt summary back. No native callback deadlock: native Swift async operations happen outside Python worker/GIL and off UI thread. Existing resolver stays independently scoped; no shell, external process, runtime code fetch, arbitrary native calls or new dependencies.
- Swift remains trust boundary. Native stage receipts bind original acquisition SHA, MKV SHA, input sample timing/format, decode timeline and decoded PCM SHA to the same job and policy. Bound jobs, bytes, frames, packets and wall-clock progress using existing acquisition/disk/cancellation limits and app PCM input bounds. Stage completion only after integrity checks and atomic publication. On restart re-verify parents and outputs, resume only from a complete verified receipt; never splice attempts. Keep prior originals, exports, voices and partial attempts; only clean own uncommitted scratch.
- Reuse MP4SampleTable → LocalMKVExport → MatroskaWriter unchanged first. New streaming reader understands only trusted writer layout but validates as hostile bytes: EBML/DocType, one unknown-size Segment with definite bounded children, 1 ms scale, known tracks, one BlockGroup per Cluster, no lacing/foreign track types, finite spans, no unchecked arithmetic, bounded VINT and binary payloads. Skip video payloads without reading them for audio extraction; require actual AAC block reads from the verified open MKV descriptor. Recheck descriptor identity/content before commit; symlink/replacement/truncation fails.
- Writer emits rounded millisecond PTS, AAC codec private data, per-block duration, seek pre-roll metadata and final positive discard padding. Treat seek pre-roll as seek metadata, not permission to trim all initial audio. Derive exact PCM frame clock from AAC sample rate/packet contract, use stored PTS to validate bounded continuity/initial offset within rounding tolerance, apply final discard padding once, and reject gaps, ambiguous edit lists, negative padding, or inconsistent packet counts. Do not synthesize samples to force equality. Verify decoder-managed priming separately against external PCM oracle before accepting the subset.
- Feed AAC access units into bounded Apple AudioToolbox conversion (cookie from Matroska CodecPrivate, packet descriptions, EOF drain) and stream a canonical local PCM file. Choose a WAV format already accepted by LocalVideoAudio and diarizer, use real sample counts as source coordinates. Preserve an explicit MKV timeline offset; first slice may reject nonzero starts rather than silently retime. Analysis refs use only derived PCM; add separate media origins for OCR/visual frames if MP4 companion is used, with source and time equivalence checked. Never fall back automatically.
- Proof wording: compatible MKV-derived audio only. Exact 10s candidate selection, evidence-driven naming/confirmation, generated speech/export, and physical-device lawful live URL are later gates, not claims made on the first slice.

## Ordered implementation and RED/GREEN gates

1. **Python stage policy and typed bridge**: add bundled module under python-resolver, bridge entry in VMPythonRuntime, stage coordinator in Swift. Write Python tests for exact stage transitions, unknown commands, changed/missing parent hashes, invalid limits and cancellation; write native fake-driver tests for opaque job scoping, no processing before consent and reacquisition only on explicit retry. Assert test failures before adding minimal implementation. Require package inventory/lock tests to verify the new bundled bytes and that no arbitrary runtime paths exist.
2. **Bounded writer-subset reader**: create VoiceMatrix/LocalMatroskaAudioReader.swift and native tests. TDD with genuine writer output and independently inspected packet payload hashes, count and timestamps; mutate EBML length, unknown-size child, lacing, multi-audio, clipped payload, final discard, non-monotonic time, symlink/replace and cancellation. Success requires packet hashes from MKV equal writer inputs while original MP4 is unavailable to the reader. Use existing retained descriptor utilities, not full-file mmap.
3. **Native AAC decode and receipt**: create MKV audio decoder adapter and native tests. Compare exact frame/time bounds and sample parity (fixed tolerance declared from AAC oracle calibration, not weakened post hoc) vs an independently decoded fixture, including endpoint marker and final padding. Test raw packet priming/padding/offset failure and cancel/restart, no output on corrupt parent. At least one licensed speaking fixture and one compatible structural fixture. A test where the decoder cannot access the MP4 and fails on substituted corrupt MKV is mandatory.
4. **Workflow integration**: connect separate opt-in MKV source mode to LocalMediaAcquisition and LocalVideoStudio. XCTest asserts event chain Python-requested → verified MKV → MKV-derived PCM → diarization input hash; negative test succeeds only when processing stops with explicit unsupported message even if a readable MP4 remains. Test preservation/restart and rights denial. Capture native evidence and exact source commit; existing acceptance tests unchanged.
5. **Follow-on, separate review**: timestamped exact10s clean candidates and confirmation (Unknown allowed), evidence provenance for caption/frame/ASR suggestions, F5 voice reference and held-out speech/share. Validate on licensed two-character clip; document automatic grouping limitation; independent device gate using a publisher-authorized YouTube/download path and actual acquired media bytes rather than resolver-only response. No publishing or IPA packaging in this plan.
