# Retained clip, real short speech gate

This is an analysis-only production pipeline probe, not a voice cloning or real-person identification benchmark. It never invokes `LocalVideoStudio.run`, reference creation, generation, separation, or training.

`python3 probes/clip-speaker-review/prepare.py NEW_DIRECTORY` hashes the repository's two licensed LibriSpeech FLAC sources against the existing pinned provenance in `probes/coreml-real-speakers/sources.json`. The original recordings are CC-BY-4.0; attribution/source links and immutable dataset revision are copied into fixture.json. No speech is synthesized, padded, repeated, or downloaded. FFmpeg decodes mono 16-kHz PCM16. Fixed first-sample crops produce 8-second one-speaker, 4+4-second sequential two-speaker, 8-second equal-half-gain overlap, 3-second/10-second endpoints, and 2.9-second refusal. The sole synthetic case is explicitly labeled 8-second silence. Destination must not exist; earlier evidence is preserved.

The macOS Swift probe compiles the actual production retained-media reader, extractor, receipt/store, diarizer and clip-review adapter. It prepares canonical stereo 44.1-kHz retained clips, analyzes them with the pinned Core ML bundle, validates current overlap policy, publishes and reloads the hash-bound sidecar, edits/reopens a clip-specific alias and verifies original source/clip/receipt bytes did not change. Below-minimum must be refused. Speech must produce a guess; sequential two-speaker must recover at least two groups; overlap must be flagged; silence must not invent groups. Failure is evidence of an unresolved limitation, not grounds to weaken the test. Full analysis JSON is retained for inspection of actual turn accuracy. Counts alone do not establish diarization accuracy or identity.

Run `.github/workflows/clip-speaker-real-model.yml` on the same source as the app/store and simulator gates. This macOS native-inference gate does not prove physical-iPhone performance, lifecycle UI behavior, or voice quality. No preview/release is created by the workflow.
